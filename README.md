# Viral genome embeddings: benchmarking genomic language models

Code and figure data accompanying the article. We compare embeddings of viral genomes
produced by several genomic language models (DNABERT-2, DNABERT-S, ViraLM, Evo2) against
a classical 4-mer spectrum baseline, layer by layer, and test how well each representation
generalises to virus orders that the models have never seen.

```
visualization/
    figure_io.py           shared paths, colour palette, save/load helpers
    main_figures.ipynb     Fig. 1-7 of the main text
    supplementary_figures.ipynb   per-model, per-layer supplementary figures
    kmer_sweep.py          k-mer word-length sweep (source of the Fig. 3 numbers)
    model_significance.py  paired tests between models + box plots and heat maps
    exploratory/           original exploratory notebooks, superseded (see its README)

results/                   OUTPUTS ONLY - everything the notebooks produce
    figure_data/           the exact numbers plotted in every figure (CSV, committed)
    figures/main/          main-text figures      (PNG + PDF)
    figures/supplementary/ supplementary figures  (PNG + PDF)
    figures/statistics/    model-comparison figures (PNG + PDF)

```

The split is deliberate: **`data/` only ever holds inputs, `results/` only ever holds
outputs.** No notebook writes into `data/`.

## How the figures are made

Every figure notebook is split into two independent stages:

| Stage | Reads | Writes | When you run it |
|-------|-------|--------|-----------------|
| **1 - Extract** | `data/metrics/**.xlsx` | `results/figure_data/*.csv` | once; the CSVs are committed |
| **2 - Plot** | `results/figure_data/*.csv` | `results/figures/**/*.{png,pdf}` | every time you restyle a figure |

Because each plot is drawn from a small CSV that is committed to git, **changing how a
figure looks never requires re-reading the Excel tables or recomputing anything** — you
re-run Stage 2 only. The CSVs also double as the machine-readable source data for the
article: `results/README.md` maps every figure to the file holding its numbers.

Both figure notebooks save each figure twice: **PNG** (300 dpi, for the manuscript) and
**PDF** (vector, editable text — `pdf.fonttype = 42`).

### Reproducing all figures

```bash
pip install -r requirements.txt
jupyter lab visualization/main_figures.ipynb          # then: Run All
jupyter lab visualization/supplementary_figures.ipynb # then: Run All
```

Both notebooks run from a clean checkout — the Stage 1 inputs (`data/metrics/`) and the
Stage 2 inputs (`results/figure_data/`) are both in the repository. They can be launched
from the repository root or from `visualization/`; the paths resolve either way.

## Reproducing the metrics from scratch

This part needs the raw genome files and GPU environments, and is not required to
reproduce the figures.

```bash
python run_pipeline.py                          # full run
python run_pipeline.py --models kmer dnabert2   # subset of models
python run_pipeline.py --skip_extraction        # recompute metrics from saved embeddings
python run_pipeline.py --pairwise_cross         # + pairwise virus-vs-virus metrics
```

The pipeline chunks the input FASTA files (2 kb chunks), extracts per-layer embeddings for
each model, and computes P@K and cross-P@K against 50 reference samples. Evo2 and ViraLM
run in separate conda environments (`evo2_env`, `viralm`) through `conda run`, because
their dependencies conflict with the rest.

`--pairwise_cross` additionally produces the tables behind **Fig. 7**:
`data/metrics/<model>/pairwise_Egovirales_vs_Mriyavirales/<metric>_matrix.xlsx`, one file
per metric in `compute_metrics.PAIRWISE_METRICS` (12 strand/direction combinations), plus
the summary `data/metrics/pairwise_cross_viruses.xlsx`.

The per-strand cross-virus tables in `data/metrics/cross_virus/` come from a separate
entry point, which is not wired into `run_pipeline.py` — run it from the repository root:

```bash
python utils/compute_cross_virus.py --latent_dir data/latent_dim --metrics_dir data/metrics --names Egovirales_preproc Mriyavirales_preproc
```

Inputs it expects, none of which are shipped with the repository (too large):

| Path | Contents |
|------|----------|
| `data/unk_viruses/` | genomes of the unseen virus orders (FASTA) |
| `data/preproc_unk_viruses/` | chunked versions of the above |
| `data/random_samples/` | 50 reference samples drawn from the ICTV set |
| `data/latent_dim/` | extracted embeddings (pickles, one folder per model) |

`visualization/kmer_sweep.py` is the same kind of computation for the k-mer baseline: it
sweeps k = 1..10 over `data/random_samples/` and writes
`data/metrics/kmer_sweep/kmer_sweep_results.xlsx`, the input to Fig. 3.

## Metrics

* **P@K** — precision among the K nearest neighbours in embedding space: the fraction of a
  sequence's K neighbours that share its class. Higher is better.
* **cross-P@K** — the same, but counting neighbours from the *other* sequence set
  (e.g. forward vs reverse complement, or one virus order vs another). Lower means the two
  sets are better separated.
* **ARI** — adjusted Rand index of a K-medoids clustering against the true labels.
* **Silhouette** — cosine silhouette score of that clustering.

## Requirements

Python 3.10+ and the packages in `requirements.txt`. Reproducing the *figures* needs only
pandas, numpy, matplotlib and openpyxl; the extraction pipeline additionally needs torch,
transformers and Biopython, plus the separate conda environments for Evo2 and ViraLM.
