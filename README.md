# Viral genome embeddings: benchmarking genomic language models

Code and figure data accompanying the article. We compare embeddings of viral genomes
produced by several genomic language models (DNABERT-2, DNABERT-S, ViraLM, Evo2) against
a classical 4-mer spectrum baseline, layer by layer, and test how well each representation
generalises to virus orders that the models have never seen.

## How the figures are made

Every figure notebook is split into two independent stages:

| Stage | Reads | Writes | When you run it |
|-------|-------|--------|-----------------|
| **1 - Extract** | `data/metrics/**.xlsx` | `results/figure_data/*.csv` | once; the CSVs are committed |
| **2 - Plot** | `results/figure_data/*.csv` | `results/figures/**/*.{png,pdf}` | every time you restyle a figure |

Because each plot is drawn from a small CSV that is committed to git, **changing how a
figure looks never requires re-reading the Excel tables or recomputing anything** — you
re-run Stage 2 only. The CSVs also double as the machine-readable source data for the
article: `results/README.md` maps every figure to the file holding its numbers.

Both figure notebooks save each figure twice: **PNG** (300 dpi, for the manuscript) and
**PDF** (vector, editable text — `pdf.fonttype = 42`).

## Reproducing the metrics from scratch

This part needs the raw genome files and GPU environments, and is not required to
reproduce the figures.

```bash
python run_pipeline.py                          # full run
python run_pipeline.py --models kmer dnabert2   # subset of models
python run_pipeline.py --skip_extraction        # recompute metrics from saved embeddings
python run_pipeline.py --pairwise_cross         # + pairwise virus-vs-virus metrics
```

The pipeline chunks the input FASTA files (2 kb chunks), extracts per-layer embeddings for
each model, and computes P@K and cross-P@K against 50 reference samples. Evo2 and ViraLM
run in separate conda environments (`evo2_env`, `viralm`) through `conda run`, because
their dependencies conflict with the rest.

`--pairwise_cross` additionally produces the tables behind **Fig. 7**:
`data/metrics/<model>/pairwise_Egovirales_vs_Mriyavirales/<metric>_matrix.xlsx`, one file
per metric in `compute_metrics.PAIRWISE_METRICS` (12 strand/direction combinations), plus
the summary `data/metrics/pairwise_cross_viruses.xlsx`.

## The distance metric as an axis (Fig. 4-6)

The distance metric is part of the representation, not a technical detail: a k-mer
profile is a probability distribution, so metrics defined on the simplex apply to it,
while an embedding is an arbitrary real vector and they do not. `utils/metric_axis.py`
therefore sweeps *protocols* — a (transform, metric) pair — over the same embeddings:

| Protocol | Transform | Metric | Representation it needs |
|----------|-----------|--------|-------------------------|
| `P0` | StandardScaler | cosine | any — the protocol behind all published tables |
| `P1` | none | cosine | any — control that isolates the effect of scaling |
| `P2` | StandardScaler | euclidean | any |
| `P3` | none | euclidean | any |
| `P4` | none | MinHash (Jaccard) | MinHash sketches — model `minhash` |
| `P5` | none | sqrt(Jensen-Shannon) | probability vectors — model `kmer` |

Those last two restrictions are mathematical, not technical. Jensen-Shannon is defined
between distributions, and mapping an embedding onto the simplex would need an arbitrary
transform. MinHash does not read a vector at all: it describes a fragment by the *set* of
its k-mers and estimates the Jaccard index between two such sets, so it needs its own
representation (see below). Inapplicable pairs are skipped; `--strict` turns the skip
into an error.

```bash
python utils/metric_axis.py --latent_dir data/latent_dim --metrics_dir data/metrics     --names Egovirales_preproc Mriyavirales_preproc
```

One pass over the neighbour lists yields P@1..P@10 and CROSS P@1..P@10, i.e. the data
behind Fig. 4, 5 and 6 at once. Results go to `data/metrics/<protocol>/<model>/`, with
the same file names as the main pipeline, plus `data/metrics/metric_axis_summary.xlsx`.
After the run, `P0` is compared against the committed tables and the script stops on any
mismatch (`--check_p0_only` checks an existing run, `--skip_check` disables the gate).
Use `--n_ref 1 --protocols P0` for a timing probe first, and `--max_workers` if memory
is tight — every process loads its own copy of scipy and of the embeddings.

### Choosing the word length on the reference viruses

For the alternative representations the word length `k` plays the role the layer plays
for a transformer: a free parameter that must not be tuned on the data the result is
reported on. `utils/k_sweep.py` picks it on the **reference** set, by the same quantity
that picks the layer (P@5 inside a reference sample), and everything downstream uses the
winner:

```bash
python utils/k_sweep.py --method js       --n_ref 10
python utils/k_sweep.py --method minhash  --n_ref 10
```

The full sweep goes to `data/metrics/k_sweep/<method>_k_sweep.xlsx` and the choice to
`data/metrics/k_sweep/best_k.json`. The chosen `k` defines its own model folder,
`kmer_k<K>` (built by `utils/kmer_profiles.py`) or `minhash_k<K>`, which
`metric_axis.py` reads like any other layer-less representation and
`metric_axis_figures.py` picks up automatically. A sub-sample of reference samples is
enough to choose a parameter, hence `--n_ref 10`; the metrics themselves are still
computed on all 50.

Sweep, extraction, metrics and figures run in one command, skipping any step whose
output already exists:

```bash
python run_alt_baselines.py
```

### MinHash sketches (protocol `P4`)

`utils/minhash_sketch.py` builds the representation `P4` needs, straight from the FASTA
files: each fragment becomes `--sketch_size` minima of universal hashes over the set of
its canonical k-mers. Canonical means `min(kmer, revcomp(kmer))`, so a sketch is
identical for a fragment and its reverse complement by construction.

```bash
python utils/minhash_sketch.py --ref_dir data/random_samples --n_ref 50 \
    --virus_dir data/preproc_unk_viruses \
    --names Egovirales_preproc Mriyavirales_preproc --rc --k 8

python utils/metric_axis.py --latent_dir data/latent_dim --metrics_dir data/metrics \
    --names Egovirales_preproc Mriyavirales_preproc --models minhash_k8 --protocols P4
```

The sketches land in `data/latent_dim/minhash_k<K>/` in the same `{label: [arrays]}`
format as every other representation, so `metric_axis.py` reads them as one more
layer-less "model".

**Choosing k matters more than the sketch size**, which is why it is not guessed but
swept on the reference set (see above). Mash uses k = 21, but that is meant for
whole genomes: on 2 kb fragments two different viruses share no 21-mer at all, the Jaccard
index collapses to zero and the metric carries no signal. At the other end, k = 4 puts
almost every word in every fragment and the index saturates at one. Measured on random
2 kb sequences, the usable range is in between:

| k | 4 | 6 | 8 | 11 | 15 | 21 |
|---|---|---|---|----|----|----|
| Jaccard of two unrelated 2 kb fragments | 1.00 | 0.45 | 0.03 | 0.0003 | 0 | 0 |

Hence the default `--k 8` when the sweep has not run. `--seed` must be identical across
every file of a run, since the sketches are only comparable under the same hash
functions.

## Metrics

* **P@K** — precision among the K nearest neighbours in embedding space: the fraction of a
  sequence's K neighbours that share its class. Higher is better.
* **cross-P@K** — the same, but counting neighbours from the *other* sequence set
  (e.g. forward vs reverse complement, or one virus order vs another). Lower means the two
  sets are better separated.
* **ARI** — adjusted Rand index of a K-medoids clustering against the true labels.
* **Silhouette** — cosine silhouette score of that clustering.

## Requirements

Python 3.10+ and the packages in `requirements.txt`. Reproducing the *figures* needs only
pandas, numpy, matplotlib and openpyxl; the extraction pipeline additionally needs torch,
transformers and Biopython, plus the separate conda environments for Evo2 and ViraLM.
